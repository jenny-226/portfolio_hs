# 양효선 포트폴리오 대시보드 — 구현 가이드

2026 KITA 채용 박람회(지원 마감 11/8, 면접 11/27) 제출용 포트폴리오를 **탭형 웹 대시보드**로 구현하기 위한 문서입니다.
이 README 하나만 보고 구조 · 레이아웃 · 문구 · 작업물 배치를 모두 구현할 수 있도록 작성했습니다. 이후 같은 구성으로 PPT를 만들 예정이므로, 각 섹션은 슬라이드 1장으로 옮기기 쉬운 단위로 나눴습니다.

## 1. 기본 원칙

| 원칙 | 내용 |
|---|---|
| 한 박스 = 한 메시지 | 박스 하나에는 하나의 내용만 담습니다. 본문은 3줄 안쪽을 목표로 하고, 길어지면 박스를 나눕니다. |
| 요점 화면만 보여주기 | 만든 화면을 전부 보여주지 않습니다. **각 사례의 해결을 증명하는 화면 1–2장만** 골라, 그 사례 바로 아래에 붙입니다. 화면 전체 캡처보다 요점 부분을 잘라낸(크롭) 이미지를 씁니다. |
| 경험 정리의 초점 | **상황 → (AI를 활용한) 해결 → 결과**만 보여줍니다. 중간 작업 과정(어떤 순서로 무엇을 했는지)은 쓰지 않습니다. |
| 말투 | 모든 본문은 **"~했습니다"** 체로 씁니다. "~했어요" 금지. |
| 정직한 표기 | 측정하지 않은 수치(시간 절감률 등)는 성과로 쓰지 않고, 각 탭 하단 각주로 밝힙니다. AI가 쓰이지 않은 해결은 "AI로 해결"이라고 표시하지 않습니다. |

## 2. 기술 스택 · 폴더 구조

- 순수 **HTML + CSS + JavaScript** (프레임워크 없음). VS Code + Live Server로 확인합니다.
- 탭 전환은 URL 해시(`#intro`, `#cosmoa`, `#reboot`, `#health`)로 처리합니다. 새로고침해도 보던 탭이 유지되고, 탭별 링크 공유가 가능합니다.

```
│   └── style.css
├── js/
│   └── main.js                 # 탭 전환, 이미지 확대(라이트박스), 빈 이미지 처리
└── assets/
    ├── cosmoa/
    │   ├── cover.png               # 헤더용 대표 화면 1장 (개발요청서 탭)

    │   │   └── pose-01.png ...     # 캐릭터 바리에이션 (선택, 최대 3장)
```

### 이미지 규칙
- **헤더 대표 화면(cover)**: 탭마다 1장만. 16:9, 가로 1600px 이상 권장.
- **사례 증거 이미지(case)**: 해결을 보여주는 **부분만 잘라서** 저장합니다. 비율은 자유롭되, 화면에서는 박스 폭에 맞춰 `object-fit: contain`으로 보여줍니다.
- 증거 이미지에서 봐야 할 부분에는 캡처할 때 **주황색 테두리(#B9480F, 3px)** 로 표시해 두면 보는 사람이 바로 찾습니다.
- Instagram 게시물: **1:1** 또는 **4:5**로 통일. 캐릭터: 투명 배경 PNG, `object-fit: contain`.
- 모든 이미지는 클릭하면 크게 볼 수 있게 합니다(라이트박스, 4장 참고). 모든 `<img>`에 내용을 설명하는 `alt`를 넣습니다.
- **이미지가 아직 없을 때**: 회색 점선 박스에 "작업물 이미지 자리 · 파일명"을 표시합니다(`onerror`로 처리). 레이아웃이 무너지지 않도록 이미지 칸은 `aspect-ratio`로 크기를 고정합니다.

```css
  --soft:#E9EAEE;     /* 박스 안 구분선 */
  --blue:#1F4FD1;     /* 포인트 · AI 해결 */
  --blue-tint:#EDF1FD;
  --orange:#B9480F;   /* 수상 배지 · 직무 기여 라벨 · 이미지 강조 테두리 */

  --dark-sub:#D5D8E0;
  --dark-acc:#9DB5FF;
  --radius:12px;
  --gap:16px;
}
```

- 글꼴: 본문 `Noto Sans KR`(400/500/700/900), 라벨 · 날짜 · 숫자 `IBM Plex Mono`(500/600). Google Fonts로 불러옵니다.
- 본문 15px · 줄간격 1.6, 박스 제목 17–20px(900), 섹션 제목 22px(900).
- 박스: 흰 배경 + 1px 테두리 + 12px 모서리. 그림자 · 그라데이션 · 이모지는 쓰지 않습니다.
- 콘텐츠 최대 폭 1120px, 좌우 여백 24px. 박스 간격 16px, 섹션 간격 40px.
- **결과 박스만 어두운 배경**(--dark)으로, 탭 안에서 가장 눈에 띄게 합니다.
- 860px 이하에서는 모든 그리드를 1열로 쌓습니다.

## 4. 공통 구성 요소

### 4-1. 상단 탭 버튼 (모든 탭 위에 고정)
- 페이지 맨 위에 고정(`position: sticky; top: 0`)되는 헤더. 왼쪽에 이름(양효선 · Hyoseon Yang), 그 아래 **탭 버튼 4개**를 가로로 배치합니다.
- 버튼: `소개` · `COSMOA` · `REBOOT` · `건강기능식품 대시보드`
- 버튼은 높이 44px 이상의 실제 `<a href="#...">` 또는 `<button>`으로 만들고, 선택된 탭은 파란 밑줄 + 진한 글씨 + `aria-current="page"`로 표시합니다.
- 모바일에서는 버튼 줄을 가로 스크롤로 처리합니다.

### 4-2. 경험 탭 공통 레이아웃 (위→아래 순서)

```
┌──────────────────────────┬───────────────────┐
│ ① 헤더 박스                 │ 대표 화면 cover     │
│  라벨 · 제목 · 한 줄 요약     │ (16:9, 1장)        │
│  배지 · 담당 칩 · 사이트 버튼  │                   │
└──────────────────────────┴───────────────────┘

┌─ ② 사례 블록 (사례마다 반복) ───────────────────┐
│ ┌──────────────┐   ┌──────────────────────┐ │
│ │ 상황 박스      │ → │ 해결 박스              │ │
│ └──────────────┘   └──────────────────────┘ │
│ ┌──────────────────────────────────────────┐ │
│ │ 증거 이미지 (요점 크롭 1–2장)                 │ │
│ │ 캡션: "이 화면에서 볼 부분 — ..."            │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘

┌─ ③ 결과 (어두운 박스) ──────────────────────────┐
│ [지표 타일] [지표 타일] [지표 타일]                │
│ ─────────────────────────────                │
│ 한 줄 요약                                     │
└──────────────────────────────────────────────┘
┌─ ④ 직무 기여 박스 ──────────────────────────────┐
└──────────────────────────────────────────────┘
  각주 (작은 회색 글씨)
```

**① 헤더 박스**
- 왼쪽(7/12): 구분 라벨(예: `PROJECT 01 · KITA AX 1차 팀 프로젝트`) → 프로젝트명(크게) → 한 줄 요약 → 수상 배지(주황) · 발표일 → 담당 범위 칩 2–3개 → **"사이트 열기 ↗" 버튼**(새 탭).
- 오른쪽(5/12): 대표 화면 cover 1장. 이 프로젝트가 어떤 화면인지 한눈에 보여주는 용도이며, 탭 전체 화면은 넣지 않습니다.

**② 사례 블록**
- 사례 하나 = 상황 박스 + 해결 박스 + 증거 이미지 박스. 블록 사이 간격은 32px로 넓게 둬서 사례가 구분되게 합니다.
- 블록 맨 위에 작은 번호 라벨(`CASE 01`).
- 상황 박스(5/12): 흰 배경, 라벨 `상황`, 2–3줄.
- 해결 박스(7/12): 라벨에 해결 방식을 표시합니다.
  - `AI로 해결` → 파란 연한 배경(--blue-tint)
  - `대시보드로 해결` / `규칙 기반 자동 판정으로 해결` → 연회색 배경(#F1F2F5)
  - 구성: **굵은 한 줄 제목 + 2–3줄 설명**
- 상황과 해결 사이에 화살표(→). 모바일에서는 위아래로 쌓고 화살표를 ↓로 바꿉니다.
- 증거 이미지 박스: 해결 박스 바로 아래 전체 폭. 이미지 1장이면 전체 폭, 2장이면 나란히(또는 Before → After). 이미지 아래 캡션은 **"이 화면에서 볼 부분 — ..."** 형식으로 한 줄.

**③ 결과 영역**
- 어두운 배경 박스. 라벨 `RESULT · 결과`.
- 지표는 **타일마다 따로**(큰 숫자 · 키워드 1줄 + 설명 1–2줄). 3–4개.
- 맨 아래 구분선 뒤에 한 줄 요약.

**④ 직무 기여 박스**
- 흰 박스 한 줄. 왼쪽 주황 라벨 `직무 기여`, 오른쪽 문장 1개.

**각주**: 12px 회색. 측정하지 않은 성과 · 가상 데이터 여부를 밝힙니다.

### 4-3. 라이트박스
- 이미지를 클릭하면 `<dialog>`로 화면 가운데에 크게 띄웁니다. 캡션 표시, `Esc` · 바깥 클릭 · 닫기 버튼(aria-label="닫기")으로 닫습니다.

  - 02 연결력 · 흩어진 업무의 공통분모를 찾아 엮습니다 — 건강기능식품 대시보드에서 사양이 바뀔 때마다 개발요청서 · 규제 · 견적을 따로 고쳐야 하는 문제를 보고, 세 문서가 결국 같은 ‘제품 사양’을 다룬다는 공통분모를 찾았습니다. 이를 기준으로 세 업무를 하나로 연결해, 사양을 한 번 고치면 규제와 견적이 함께 따라오게 했습니다. / 결과: 세 곳을 따로 재확인 → 한 곳만 수정
  - 03 구현력 · 떠올린 해결책을 AI로 직접 구현합니다 — COSMOA에서 담당자가 바이어 요청서를 매번 번역 · 재작성하는 문제를 보고, 아이디어 제안에 그치지 않고 AI 툴을 대시보드에 직접 연동했습니다. 요청서를 업로드하면 조건이 추출되어 개발요청서 초안이 채워지도록 만들어, 비개발 직무지만 해결책을 실제로 작동하는 형태로 내놓았습니다. / 결과: 요청서를 처음부터 재작성 → 초안을 검토만
