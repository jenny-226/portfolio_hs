CASE 01

AI로 해결

요청서를 매번 다시 쓰던 문제를, AI가 필요한 조건을 골라 초안을 채우게 해 풀었습니다

바이어 요청서는 언어와 양식이 제각각이라, 담당자는 요청서가 올 때마다 번역하고 필요한 조건을 골라 연구소용 양식으로 처음부터 다시 써야 했습니다. 저는 개발요청서 탭에 OpenAI API를 연동해, 요청서 파일을 올리면 연구소용 항목에 맞춰 초안이 자동으로 작성되도록 구현했습니다. 원문에서 찾지 못한 값은 비워 ‘확인필요’로 표시되게 해, 담당자는 번역 · 재작성 없이 초안을 원문과 대조해 보완하는 데서 바로 시작합니다.

  • 만든 것요청서 업로드 → 개발요청서 초안 생성 기능, 항목별 확인 상태(확인 완료 / 확인필요) 표시
  • 확인한 것더미 데이터로 만든 PDF 요청서에서 변환 흐름이 작동하는 것을 확인했습니다
  • 검증 전추출 정확도와 실제 업무 시간 변화는 측정하지 않았습니다. 설계상 DOCX · XLSX · 이미지도 받도록 했지만, 이 페이지에는 PDF 사례만 제시합니다

CASE 02

AI로 해결

탭마다 개발요청서를 다시 열어 대조하던 일을, 데이터 연동으로 자동 조회되게 바꿨습니다

개발요청서 · 규제 · 제형 정보가 따로 관리되면, 다른 탭에서 조건을 확인할 때마다 개발요청서를 다시 열어 눈으로 대조해야 했고, 어긋난 조건은 연구소에 넘어간 뒤에야 드러날 수 있었습니다. 저는 AI를 활용해 개발요청서에 작성된 값을 공통 데이터로 저장하고, 규제 데이터(CSV) · AI 제형 시뮬레이션 탭과 연동하는 로직을 구현했습니다. 개발요청서 내용이 두 탭에 자동으로 반영되고 필요한 항목이 바로 조회돼, 담당자는 탭을 오가며 대조하지 않고 확인 필요 항목과 수출국 규제 확인 알림을 보고 누락 · 불일치를 정리한 뒤 전달합니다.

  • 만든 것입력 완료 수, 확인 필요 항목, 수출국 규제 확인 알림을 모은 문서 정보 패널
  • 확인한 것변환 예시에서 27개 중 18개 입력, 확인 필요 3건(요청 구분 · 샘플 구분 · 목표 가격대), 프랑스 · 독일 규제 확인 필요가 표시되는 것을 확인했습니다
  • 검증 전실제 연구소 전달 후 재질문이 줄어드는지는 확인하지 않았습니다

RESULT · 업무가 이렇게 바뀌었습니다

담당자는 요청서를 다시 쓰지 않고, 빠진 데이터 없이 연구소에 넘깁니다

이전이후

  • 직접 작성 → 초안 검토

    이전요청서가 올 때마다 담당자가 번역 → 조건 선별 → 국문 양식 재작성을 손으로 거쳤습니다

    →

    이후요청서를 업로드하면 연동된 AI 툴이 개발요청서 초안을 채우고, 담당자는 검토만 합니다

  • 탭마다 눈으로 대조 → 한 번에 일치 확인

    이전개발요청서 · 규제 · 제형 정보를 따로 열어 맞춰 봤고, 빠지거나 어긋난 조건은 연구소 전달 후에야 드러났습니다

    →

    이후세 탭이 같은 데이터로 연동되어, 조건이 맞는지 바로 확인하고 빠짐없이 넘깁니다

직무 연결 · 해외영업

바이어의 요구를 연구소가 검토할 수 있는 제품 개발 조건으로 구체화하고, 빠진 조건은 전달 전에 바이어에게 먼저 확인하겠습니다.

* 변환 예시에 사용한 요청서는 더미 데이터입니다. 추출 정확도와 업무 시간 절감률은 측정하지 않았습니다.

여러 도구에 흩어진 미국 인플루언서 협업 업무를, AI로 구현한 파트너 탭 하나로 이었습니다

미국에 숙취해소제를 수출하는 마케팅 실무자는 현지 인플루언서를 찾고, 영어로 제안하고, 콘텐츠에 효능을 과장하는 표현이 들어가지 않았는지까지 챙겨야 합니다. 이 일이 여러 도구에 흩어져 있어 제안할 때마다 브랜드 · 제품 정보를 영어로 다시 쓰고, 쓰면 안 되는 표현은 규정을 따로 찾아 대조해야 했습니다. 저는 AI를 활용해 인플루언서 정보를 API로 불러오고, 브랜드 · 제품 정보와 협업 이력을 DB에 저장하는 로직을 구현해, 후보 탐색 → 영문 제안 → 가이드 검토 → 협업 관리가 한 화면에서 이어지는 파트너 탭을 만들었습니다. 저장된 정보는 영문 제안 초안에 자동으로 들어가고, 가이드 검토 단계에서는 규제 데이터(CSV)에 등록된 금지 표현이 바로 표시돼, 담당자는 다시 쓰거나 규정을 찾지 않고 확인한 뒤 보냅니다.

  1. 후보 탐색
  2. 영문 제안
  3. 가이드 검토
  4. 협업 관리
  • 만든 것인플루언서 정보 API · 브랜드 정보 DB 연동, 영문 제안 초안 자동 입력, 금지 표현 표시가 들어간 4단계 파트너 탭
  • 확인한 것대시보드에서 단계 흐름과 제안 초안 생성이 작동하는 것을 확인했습니다
  • 검증 전실제 인플루언서 섭외 · 파트너 계약 적용은 확인 자료가 없어 결과에 넣지 않았습니다

RESULT · 업무가 이렇게 바뀌었습니다

소규모 팀이 기획에서 콘텐츠 집행, 인플루언서 협업까지 기다림과 중복 작업 없이 이어가도록 했습니다

이전이후

  • 시안 제작 대기 → 기획 즉시 콘텐츠화

    이전시즌 제품 콘셉트를 보여주려면 실물 패키지나 별도 디자인 작업이 끝나기를 기다려야 했습니다

    →

    이후생성형 AI로 Original · Balance 2개 라인의 할로윈 디자인을 바로 시각화해, 기획 단계에서 곧장 피드 게시물로 집행했습니다

  • 여러 도구 오가기 → 탭 하나

    이전후보 조사 · 영문 제안 · 협업 관리를 각각 다른 곳에서 처리하며 화면과 자료를 오갔습니다

    →

    이후파트너 탭 하나에서 후보 탐색부터 협업 관리까지 4단계가 끊기지 않고 이어집니다

  • 매번 재입력 → 한 번 입력

    이전인플루언서에게 제안할 때마다 브랜드 · 제품 정보를 처음부터 다시 적어야 했습니다

    →

    이후한 번 입력한 정보가 영문 제안 초안에 자동으로 다시 쓰여, 제안서는 확인 후 바로 보냅니다

직무 연결 · 마케팅

해외 소비자에게 낯선 한국 제품을 현지 시즌과 생활 장면에 연결해 제안하고, 콘텐츠 시안부터 인플루언서 · 파트너 협업 준비까지 이어가겠습니다.

* 팀 전체 기록(외부 출처 17곳 · 경쟁 제품 80개 · 브랜드 39개 · 게시물 121개)과 개인 기여를 구분했습니다. 소비자 반응 · 매출 · 전환율은 측정하지 않았습니다.

PROJECT 03 · 개인 프로젝트

건강기능식품 해외영업 대시보드

누구에게 먼저 연락할지 정하기 어려운 바이어 발굴과, 국가 조건까지 챙겨야 하는 개발요청서 작성을 AI를 활용해 하나의 도구로 풀었습니다

  • 개인 프로젝트 · 기획 · 구현 · 배포
  • 바이어 발굴 → 개발요청서 → 견적
건강기능식품 대시보드 열기 ↗ 로그인 없이 볼 수 있음 · 가상 데이터

혼자 수행한 범위

  • 기획 바이어 발굴 → 규제 확인 → 개발요청서 → 원가 · 견적 업무 흐름 설계
  • 구현 AI 도구를 활용해 적합도 계산 · 국가별 규칙 · 탭 화면을 직접 코드로 구현
  • 배포 Vercel 웹 배포, 데이터는 브라우저에 저장 · 백업 파일로 내보내기

구현 상태

  • 작동 바이어 적합도 정렬 · 제안 메일 템플릿 · 영업 관리, 개발요청서 작성과 국가 조건 반영, 규제 1차 확인, 원가 · 마진 시뮬레이션
  • 연동 예정 요청서 AI 자동 정리 · 제안 메일 AI 다듬기(OpenAI), 실제 바이어 데이터 수집, ERP 원가 연동 — 서버가 필요한 2단계

CASE 01

AI로 해결

누구에게 먼저 연락할지 정하기 어렵던 바이어 발굴을, 우리 제품과 맞는 순서로 정렬했습니다

잠재 바이어 목록이 있어도, 그 바이어가 우리가 만들 수 있는 제형 · 원료를 취급하는지, 요구 인증과 거래 형태가 맞는지는 홈페이지를 하나씩 열어 판단해야 해서 누구부터 연락할지 정하는 데 시간이 걸렸습니다. 저는 AI를 활용해 바이어 리스트 데이터와 자사 제조 역량 데이터를 같은 기준(제품군 · 제형 · 원료 · 거래 형태 · 인증 · 국가 진입 준비)으로 비교해 적합도를 계산하는 로직을 구현했습니다. 기준 제품 하나만 고르면 바이어가 적합도 순으로 정렬되고 점수의 근거가 함께 표시돼, 담당자는 홈페이지를 하나씩 열지 않고 먼저 연락할 바이어를 고른 뒤 같은 탭에서 제안 메일과 후속 연락까지 이어갑니다.

  • 만든 것영업 적합도 정렬, 바이어 카드(포트폴리오 · 자사 생산 비교 · 적합도 구성), 제안 메일 템플릿, 영업 관리 보드
  • 확인한 것가상 바이어 데이터로 기준 제품을 바꾸면 순위와 근거가 함께 바뀌는 것을 확인했습니다
  • 검증 전적합도는 구매 확률이 아닌 우선순위 지표입니다. 실제 바이어 데이터 수집과 제안 메일 AI 다듬기는 연동 예정입니다

CASE 02

AI로 해결

국가 규제 조건을 따로 찾아 옮겨 적던 개발요청서 작성을, 규제 확인 결과가 바로 반영되게 바꿨습니다

건강기능식품 개발요청서는 바이어 요청을 옮겨 적는 것만으로 끝나지 않고, 수출 국가에서 쓸 수 있는 표시 문구 · 금지 원료 · 필요한 근거 자료까지 담아야 합니다. 그래서 담당자는 국가별 규정을 따로 찾아 확인한 뒤 요청서에 다시 옮겨 적는 이중 작업을 해야 했습니다. 저는 AI를 활용해 국가별 규제 데이터를 규칙 ID · 출처가 붙은 구조로 정리하고, 성분표(CSV · XLSX)와 개발요청서 문구를 이 데이터와 자동 대조하는 로직을 구현했습니다. 대조 결과는 개발요청서의 국가 조건 · 법규 금지 원료 · 근거 자료 요청 항목에 자동으로 반영되고, 문구가 바뀌면 다시 대조돼 결과가 달라질 때 알림이 뜹니다. 담당자는 규정을 따로 찾아 옮겨 적지 않고, 규칙이 없는 국가나 영역(‘규칙 미등록’)만 직접 확인합니다.

  • 만든 것국가별 규제 규칙과 1차 확인, 개발요청서 국가 조건 자동 반영, 규제 결과 변경 알림
  • 확인한 것가상 제품으로 규제 확인 결과가 개발요청서에 반영되고, 문구를 바꾸면 다시 확인되는 것을 확인했습니다
  • 검증 전규칙은 사전검토용 1차 참고이며, 규제 전문가 검토와 실무 사용은 거치지 않았습니다

CASE 03

설계 단계 · 연동 예정

다국어 요청서 자동 정리를 위한 입력 · 검토 구조를 설계했습니다

건강기능식품 바이어 요청서도 RFP · Product Brief 등 양식과 언어가 제각각이라, 개발요청서로 옮기는 작업이 반복됩니다. 저는 COSMOA에서 쓴 방식을 이 산업에 맞게 옮겨, 개발요청서 탭에 OpenAI API를 연동할 업로드 · 검토 구조를 설계하고, 원문에 없는 값은 ‘미입력’으로 남기는 원칙을 정했습니다. 서버 · AI 연동 전이라 현재 배포본에서는 같은 양식을 직접 작성합니다.

  • 만든 것업로드 · 검토 화면과 변환 원칙 (화면 구성까지)
  • 현재 상태서버 · OpenAI 연동 전이라, 현재 배포본에서는 같은 양식을 직접 작성합니다
  • 검증 전자동 정리 기능은 아직 작동하지 않으며, 시간 절감 효과는 연동 후 확인이 필요합니다

RESULT · 구현한 기능과 예상 업무 변화

바이어를 찾는 순간부터 개발요청서를 넘기기까지, 다시 찾고 옮겨 적던 일을 하나의 흐름으로 연결했습니다

구현한 기능예상 업무 변화

  • 바이어 우선순위

    구현기준 제품과 자사 생산 역량으로 바이어를 적합도 순으로 정렬하고 근거를 보여줍니다

    →

    예상홈페이지를 하나씩 보기 전에, 먼저 연락할 바이어를 근거와 함께 고를 수 있습니다

  • 국가 조건 반영

    구현규제 확인 결과가 개발요청서의 국가 조건 · 금지 원료 · 근거 자료 항목에 들어갑니다

    →

    예상규정을 따로 찾아 옮겨 적는 일이 줄고, 담당자는 규칙 미등록 항목을 중심으로 확인합니다

  • 사양 변경 알림

    구현문구가 바뀌면 규제 확인이 다시 실행되고, 결과가 달라지면 개발요청서에 알림이 뜹니다

    →

    예상변경 시 다시 확인할 항목을 놓치지 않도록 돕습니다. 확인 자체는 담당자가 합니다

  • 다국어 요청서 정리 설계 단계

    구현입력 · 검토 구조와 원칙을 설계했고, AI 자동 정리는 연동 예정입니다

    →

    예상효과는 연동 후 확인이 필요합니다

직무 연결 · 해외영업

제품과 맞는 바이어를 근거를 갖고 먼저 고르고, 바이어 요청을 수출 국가 조건까지 담은 개발요청서로 정리해 넘기겠습니다.

* 화면 속 기업 · 제품 · 점수는 기능 설명용 가상 데이터입니다. 규제 규칙은 기관 자료 · 공개 자료를 바탕으로 정리했고(기준일 2026.11.04), 판정은 사전검토용 1차 참고입니다. 최종 판단은 규제 담당과 현지 바이어(명의자)가 합니다. 시간 단축률은 측정하지 않았습니다.
